### Bataroc J-67 发言

**一、议题一：Agent 统计实操手册（阶段性展示，未定稿）**

- 展示《JV PoWH 统计从取数到 PR 的完整路径（agent 实操手册）》：不是人写一份"我心目中的流程"，而是 agent 在 7 月做完核对、8 月做完完整统计与自查闭环之后，自己总结出的可复现路径，任何零背景的新 agent 照做即可。
- 手册结构：思想层（单一真相源、可追溯可反查、双向互链）→ 采集层（链上签到与多签、GitHub 非标评论、纪要与 blog 署名）→ raw 溯源表 → 汇总表；另附八步流程与 16 条踩坑清单。
- 下一步：等 9 月统计再跑一遍闭环后迭代定稿；定稿前需明确这份手册 PR 到哪个仓库（原拟会上问教链 J-25，其缺席，会后私信确认）。

**二、议题二：新版数据溯源表（raw）迁入 GitHub**

- 迁移动机：飞书是个人账号平台，不适合作为公开、可核对的统计载体；raw 表取代原飞书明细表，作为统计链条的第一层。
- 沿用前几次会议共识：当月无数据的 WP 不建列（飞书是全部列都列出）；备注由 agent 自动生成，含表性质与定位、表头读法、WP-1 多签、无数据不建列、数据源清单与取数链接、数值核对方式。
- 数据已与微尘 J-53 手工飞书表逐项核对无差异、群内暂无异议；本意是本次展示后即可合并，并与执行空投用的汇总表置于同一目录。

**三、非标上报截止时间（回应微尘 J-53）**

- 现共识是次月 1–10 日报上月，但"干完即报"是自然的工作习惯，不宜因为截止日把"上报"本身变成一项被限制的工作。
- 建议改为：当月月末前一日报当月，统计在次月统计上月——与公司发薪记账同理（1–31 日的工作、次月 10 日发），可消除"当月上旬报的算哪个月"的归属歧义。

**四、agent 的遗忘与漂移（回应微尘 J-53）**

- 遗忘是必然的，但可控：把关键规则写入 agent 的系统文件，相关对话时自动进入上下文。
- 漂移靠"跑通—纠偏—再跑"收敛：人能看到出错位置并纠正，漂移逐步减少直到稳定再固化，最后让 agent 总结成手册；只要取数源头与上报口径不变，流程就不会漂。
- 规程的产生顺序：不是先凭空设计一份范本再让 agent 执行，而是让 agent 按既有规章走完全程、产出正确的 raw 表，再由它总结成规程——结果可验证，规程才有锚。

**五、其他**

- 留痕要求：任何标准/非标工作都须有 GitHub 留痕；对微尘 J-53 新做的投票、签到徽章画廊前端，需给出 PR 所在仓库与链接，便于他人查看核对。
- rev9 计件标准疑似少列一项（统计/复核的口径），会后对照 rev8 原文再与教链 J-25 核实。
- 对旁听成员的建议：先做一两个工作包（如会议主持）成为被统计对象，再看统计表就能理解 PoWH 与这份手册。
