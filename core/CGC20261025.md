### Bataroc J-67 发言

**一、议题：统定统计组月总包工时与分项（WP-3），并溯源现有标准的由来**

- 规范：rev8 第 3.6 条与 rev9（v2）WP-3「A 标准化工作项」口径一致，均为 **9h**——统计 4h（含协调跟踪 1h）+ 录入 2h + 合并 1h + 执行 2h，**无「统计主管」项**。
- 实际：2026.1 起入表为 **11h**——统计主管 2h + 统计 4h + 录入 2h + 合并 1h + 空投执行 2h。
- 结论：规范与实际执行长期不一致，每月相差 2h，已连续执行约 9 个月。

**二、溯源（请优先追查）**

- 11h 这套口径出自哪一版、哪次会议、哪份会议纪要？是试行版写错了，还是实际执行超出规范？
- 对照线索：REV-4 到 REV-9 的转变——REV-4 首次提出 5h；REV-5 扩到 9h；REV-6 不涉及统计工时；REV-7 引入统计主管概念，但总包退回 8h；REV-8、REV-9（v2）又回到 9h，前后无一脉相承的脉络。（REV-1 至 REV-3 时期，WP-3 尚属非标工作范畴。）

**三、请会议决议**

1. 统计组月总包小时数（9h 或 11h）。
2. 固定总包内的分项名称及各自对应工时，且须满足「总包 = 各分项之和」。
3. 依决议修订 v2（rev9）WP-3 相应内容，提 PR 并出会议纪要留痕；后续变更 WP-3 计件标准须走同一程序（CGC 讨论 + 纪要）。

**四、此刻提出的原因**

- 我 2026 年 1 月加入统计组，沿用微尘 J-53 设计的表格，月统计含空投执行合计 11h，一直照填。
- 近两周编写「统计操作规程」时，agent 指出规程（REV8/REV9）写 9h、实际入表 11h，差 2h，才开始回溯版本。
- 微尘 J-53 近忙，统计组仅我一人；原规则下单人须减 2h（会上确认：单人无统计主管工作量，应为 7h）。
- 给 agent 的规程即将定稿，这一条必须先写准；v2（REV9）WP-3 条款需确认一次。

**五、我的态度**

- 多 2h 对我个人有利，正因如此更应公开讨论，而非默默延续。
- 这等于「给自己定发工资的规则」，规则与执行不符就该交 CGC 定。
- 必须二选一：按规范 9h → 明确调整时点、以往差额是否退回；按实际 11h → 修订 v2 对齐。

**六、会上结论**

- 数字脉络经微尘 J-53 讲清并互相印证：统计4+录入2+合并（检查核对）1=7h；设轮值统计主管加 2h（发群通知、检查复核）=9h；再加空投执行 2h=11h。
- 即：两人轮值 11h/月（统计侧 9＋空投执行 2）；单人统计 9h/月（统计侧 7＋空投执行 2）。
- 往年数字不按多算处理：统计主管 2h 源自统计组成立时经会议通过的轮值设计，程序已走完；问题在 REV8/REV9 未写明「统计主管 2h（轮值）」，致 agent 读规程漏项。
- 口头确认：空投执行 2h 归当月执行人。

**七、后续动作**

- 依教链 J-25 建议：修订 REV8 前完成 open-meetings 全量会议纪要交叉查证，查证结果随 PR 附上；若查证与此不符，则重新提交 CGC 讨论。
- 修订 REV8 与 v2（REV9）的 WP-3，逐项写明分项名称与工时，与总包（两人 11h / 单人 9h）对齐。
- 规程定稿后招募一人，恢复「一人统计 + 一人核对」。

**八、其他**

- 总包内部如何拆分不影响执行（认真干完即拿整个总包），本议题只解决「规范 = 实际」与「标准来源可追溯」。

### 教链 J-25 发言

**一、上周工作汇总**

- 主要配合微尘做区块链浏览器（explorer）的代码审计。微尘目前在尝试用 AI agent 做开发，提交了多个 PR；教链这边负责审计、合并与发布。

**二、chainlist 链配置参数更新计划**

- 背景：MetaMask 新版本已支持直接从 chainlist（开源项目）搜索并一键添加 EVM 兼容链，Jouleverse 已在其中，用户无需再手动输入参数。教链据此复查了当初登记的配置参数，计划做三项更新后提交开源社区审查：
  1. **RPC 端点**：现在登记的是带 `:8503` 端口的地址，计划改为走 HTTPS 默认端口（443），即参数中不再写端口号，更规范、更好看。
  2. **链名称**：现为 `jouleverse mainnet`，计划去掉 `mainnet`，直接叫 `jouleverse`。理由：主流命名已不再给主网加 mainnet 后缀——Ethereum 原先叫 ethereum mainnet，现在就叫 ethereum；Unichain 主网叫 unichain，测试网才另起 unichain testnet 的名字。
  3. **链图标**：原配置没有 logo（需先把图标上传 IPFS，再在配置中引用 IPFS 链接）。教链已准备好 logo 图并上传至 IPFS，后续需向该开源项目提交、争取被接受。
- 三项参数更新在正式提交前会先发到群里，请大家看看参数是否合适，有意见可以提，再提交社区审查。
- Jouleverse 最早被收录进这个开源链数据库，是社群早期一位成员提交的，建议后续对其表示一下感谢。

**三、对「WP-3 统计组月总包工时」议题的意见**

- 既然要从 REV-8 开始改，那么之前每个月的统计表格都是以 REV-8 为参考规范的；REV-8 若不修订，前后账目就对不上。
- 当时开会应该已形成共识，只是没有及时回写进 REV-8；相关讨论应能在 open-meetings 的历史会议纪要里翻到。建议修订 REV-8 时让 agent 通翻 open-meetings 全部会议纪要，定位到当时那次会议，并把出处一并列上，相当于做一次交叉查证。
