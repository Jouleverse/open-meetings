### 微尘 J-53 发言:

1. 汇报了8月份、9月份的统计工作;

2. 会议聊天窗口贴文字汇报了rev8与rev9的异同,提出rev9版本的截止时间考虑每年五一、十一节日放假特殊情况,建议非标工作量上报截止时间改为次月10日24时.

3. 提出完成9月份统计岗工作后暂时退出统计组工作,交回github统计数据合并权限.

4. 会后起草agent统计规程草案转J-67总结定稿.

### 教链(evan) J-25发言要点

1. **关于非标工作量上报截止时间（rev9 试行版）**
   - 赞同将非标上报截止时间调整为次月 **10 日 24 时**，正好覆盖五一、十一长假问题。
   - 确认 9 月未签到**只影响记账节点**，不影响非标工作量上报。
   - 建议：rev9 既是"试行版"，会后**直接提 PR 改成 10 号**先试行，运行数月稳定后再经共识机制转为正式版。

2. **肯定统计岗交接，并对继任者提建议**
   - 感谢微尘担任 PoWh 统计岗期间的贡献——把工作从"主观收集"推进到"客观来源、可由 AI agent 全自动完成"，是很大的提升。
   - 对继任的**巴错**提两点建议：
     1. 把现有自动化流程**沉淀、梳理成一份"给 agent 看的操作手册"**：让一个毫无背景知识的新 AI agent 也能照着手册自动处理（数据从哪抓、流程一步步怎么走）。
     2. 在此基础上**继续从社区招募新鲜血液**加入，与巴错互相备份、轮值、互补，避免其忙时无人替补。

3. **关于"AI agent + 区块链 + 学习活动"（Jouleverse 学习活动）的激励机制**
   - 指出该学习活动（现有 5 位发起人）**缺少激励机制**，纯凭一腔热情难以持久、难以真正投入。
   - 区分两个层面：**学员层面**（能学到智能体等知识，可免费甚至付费参加，暂不考虑其激励）；**组织／教员层面**（发起人、助教要负责张罗、宣传、招生、盯学习、查作业等大量工作量，目前没有任何机制），担心没激励做不下去、做不长久。
   - 提出激励来源问题：若用 core 的 PoWh 工作量出，项目性质就变了（"又二的项目了"）；对用生态板块赞助额度设激励池等思路，赞同在会上与 GitHub 继续深入讨论。

4. **关于教链应用对接的性能/投资问题**（回应微尘）
   - 认为应先**评估对方的实际性能需求与实现方式**（是否需要改链），先明确"对方到底要做什么"，待参数明确后再议投资出资方。

5. 其他：协助排查微尘添加腾讯云客户经理企业微信失败的问题，答应后续再推送名片。
